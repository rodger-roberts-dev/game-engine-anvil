# Goblin Engineering

**A creative workshop within Steel & Code**

> If it works, it's engineering. If it explodes, it's research.

## Identity

Goblin Engineering is the playful engineering and creative identity behind our custom game-engine work. It is **not** a separate company or repository at this stage.

- **Parent studio:** Steel & Code
- **Workshop identity:** Goblin Engineering
- **Engine:** Goblin Anvil
- **Games:** Projects built with the engine, including STEELCAST

The name reflects curious builders, inventive experiments, retro-computing nostalgia, and the joy of making things work—even when the workbench looks a little chaotic.

## Character and tone

Our imaginary shop is run by a mischievous goblin engineer in oversized goggles, carrying a wrench and a coffee cup. The humor is part of the personality, but the engineering should be practical and dependable.

**Mascot concept:** A friendly coffee-fueled goblin engineer. This is a creative concept, not yet final logo artwork.

## Principles

1. **Keep it simple (KISS).** Prefer a working, understandable solution over extra infrastructure.
2. **Build games.** Engine work should help create playable experiences.
3. **Experiment with purpose.** Learn from prototypes, keep the useful parts, and discard unnecessary complexity.
4. **Craftsmanship over ceremony.** Test, document, refine, and ship.
5. **Have fun.** The workshop should be a place for curiosity, nostalgia, and creativity.

## Repository policy

For now, Goblin Engineering is an identity documented **inside** the existing `game-engine-anvil` repository. Create separate repositories only if an independently useful tool or project actually needs its own lifecycle.

## Relationship to the engine

Goblin Engineering is **who is at the workbench**; Goblin Anvil is **what is being built on the workbench**.
